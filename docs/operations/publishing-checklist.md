# Publishing Checklist

每篇文章发布前必须通过这份检查。任何一项失败，都先修改或暂缓发布。

## Research Quality

- 标题准确，不夸大收益，不伪装成官方公告。
- 正文有完整段落，不是提纲、短句堆叠或关键词拼接。
- 至少包含一个真实贡献：论文机制拆解、源码路径分析、实验过程、评测方法、失败复盘、数据观察或明确判断。
- 论文类文章必须写清研究问题、方法、实验设置、主要结论和局限。
- 开源项目类文章必须阅读仓库结构和关键实现，不能只复述 README。
- 优化建议必须写清适用场景、代价、失败模式和可验证指标。
- 没有保留“作为 AI”“本文将”“总之很重要”等空泛套话。
- 没有新论文、新项目、新实验或新判断时，不强行发布。

## Originality And Sources

- 不采集、不洗稿、不改写第三方文章当原创。
- 涉及论文、仓库、工具能力、API、模型能力或基准结果时，确认当前来源和日期。
- 使用短引用时标明来源；大段内容必须转述为自己的实践结论。
- 文章中的命令、路径和配置来自当前仓库或明确说明为示例。

## Technical Integrity

- 不把猜测写成事实，不用“最佳”“颠覆”“完全解决”等无法支撑的表述。
- 结论区分证据、推断和个人判断。
- 对过时技术、重复概念或没有实质增量的内容，选择不发布。
- 如使用 AI 辅助写作，必须进行事实核对、术语统一和人类可读性重写。

## Technical Gate

- 运行 `npm run build` 并确认退出码为 0。
- 检查文章 URL、分类、标签、RSS、sitemap、robots 是否仍能生成。
- 构建产物、依赖目录、临时文件不进入 Git。
- 发布前查看 `git diff --stat`，确认没有无关改动。
